# PV Observation Enhancement (Pattern Recognition + Capacity estimation) & Forecasting Pipeline

This repository provides a complete workflow for learning representative PV generation patterns, estimating system capacities, and performing day-ahead forecasting using **CNN-LSTM**, **XGBoost**, and **Procrustes alignment**.

All input files can be placed in a local `data/` folder located in the same directory as these notebooks and scripts. No absolute paths are required.

## 2. Data Files (all under `./data/`)

| File | Description |
|------|--------------|
| **PV_power_GHI.csv** | Time series with two columns: `solar_radiation` and `pv_power`, sampled every 15 min (96 steps/day). |
| **Y_list.csv** | Daily PV power profiles normalized by the total installed capacity, i.e., each element represents *measured power ÷ total capacity*. |
| **c_ratio_pecan.csv** | Directional capacity ratios of each system, defined as \( c_{n,d} / c_n^{\text{tot}} \) for south-, west-, and east-facing arrays. |
| **D_orth.csv** | Learned orthogonal dictionary (output of `ShrPVProfile.ipynb`). |
| **X_orth.csv** | Concatenated sparse codes \([South | West | East]\) (output of `ShrPVProfile.ipynb`). |
| **split_days.csv** | Train/validation/test day indices generated by CNN-LSTM training. |
| **Capacity_Data.csv** | Aggregated capacity dataset combining: (i) **registered PV systems** from Pecan Street metadata and (ii) **misreported/incomplete PV systems** corrected via `Capacity_estimation.ipynb`. This file provides total capacity per azimuth direction (`South-Facing`, `West-Facing`, `East-Facing`) and is used in the Procrustes step. |

## 4. Workflow Overview

### **Step 1 — ShrPVProfile.ipynb**
Learn an orthogonal dictionary of representative PV profiles.

**Inputs**
- `Y_list.csv` — normalized daily PV power (measured power / total capacity).  
- `c_ratio_pecan.csv` — directional capacity ratios per system \(c_{n,d}/c_n^{\text{tot}}\) from Pecan Street metadata.

**Outputs**
- `D_orth.csv` — learned dictionary with orthonormal columns.  
- `X_orth.csv` — concatenated sparse codes \([South | West | East]\).

---

### **Step 2 — Capacity_estimation.ipynb**
Estimate effective PV capacities and create normalized azimuth-specific average profiles.

**Inputs**
- `Y_test_1.csv` — PV power measurement \(Y_n^{\text{mea}}\)  
- `Y_s_ave.csv`, `Y_w_ave.csv`, `Y_e_ave.csv` — normalized PV profiles per azimuth from unique-azimuth PV systems
- `D_orth.csv`, `X_orth.csv` — from Step 1

**Output**
- `Capacity_Data.csv` — **aggregated capacity data**, merging:  
  1. **Registered PV systems** — extracted from official Pecan Street metadata.  
  2. **Misreported or incomplete PV systems** — re-estimated through this notebook using the learned dictionary.  

This dataset provides corrected total capacity per azimuth (South, West, East) and supports the Procrustes PV forecasting analysis.

---

### **Step 3 — PV_forecast.ipynb**
Perform day-ahead forecasting using three methods.

#### (a) CNN-LSTM
Generates train/validation/test splits and baseline predictions.

```python
csv_path  = "./data/PV_power_GHI.csv"
out_dir   = "./data/cnn_lstm_5d"
```

Outputs:
- `split_days.csv` (shared by all methods)
- Model predictions and metrics.

---

#### (b) XGBoost
Trains a regression model to predict next-day PV power from solar radiation.

```python
csv_path             = "./data/PV_power_GHI.csv"
split_days_csv_path  = "./data/split_days.csv"
out_dir              = "./data/single_r2p"
```

Outputs:
- `Y_test.csv`, `Y_pred.csv`
- `xgb_report.json` — MAE, RMSE, MAPE + training & inference time.

---

#### (c) Procrustes
Uses dictionary-based Procrustes alignment to reconstruct aggregated PV power.

```python
CSV_DATA_PATH = "./data/PV_power_GHI.csv"
D_ORTH_CSV    = "./data/D_orth.csv"
X_ORTH_CSV    = "./data/X_orth.csv"
SPLIT_CSV     = "./data/split_days.csv"
CAPACITY_CSV  = "./data/Capacity_Data.csv"
OUTPUT_DIR    = Path("./outputs_procrustes")
```

Outputs (per season):
- `A_S.csv`, `A_W.csv`, `A_E.csv` — transformation matrices  
- `R_S.csv`, `R_W.csv`, `R_E.csv` — orthogonal matrices  
- `Y_pred_total.csv`, `Y_real_total.csv` — predicted vs. ground-truth power  
- `metrics.json` — MAE/RMSE/MAPE + iteration info   
- `summary.json` — four-season performance summary

## 5. Seasonal & Temporal Settings

- **Resolution:** 96 steps/day (15 min)  
- **Daylight window:** `ROW_SLICE = slice(19, 85)` ≈ 06:30 – 20:30  
- **Season definition (by day index):**  
  - Winter = 1–31, 305–365  
  - Spring = 32–120  
  - Summer = 121–212  
  - Fall    = 213–305

##  6. How to Run

1. **Run `ShrPVProfile.ipynb`** → produces `D_orth.csv`, `X_orth.csv`  
2. **Run `Capacity_estimation.ipynb`** → produces `Capacity_Data.csv`  
3. **Run `PV_forecast.ipynb`**  
   - (a) CNN-LSTM → creates `split_days.csv`  
   - (b) XGBoost
   - (c) Procrustes → saves results under `./outputs_procrustes/`

## 7. Troubleshooting

| Issue | Possible Cause / Solution |
|--------|----------------------------|
| `FileNotFoundError` | Ensure all required CSVs exist under `./data/`. |
| `KeyError: column not found` | Check that `PV_power_GHI.csv` has `solar_radiation` and `pv_power`. |
| Empty seasonal splits | Verify `split_days.csv` indices and total days. |
| Shape mismatch warnings | Both irradiance and PV data must have equal lengths (multiple of 96 samples/day). |
| Numerical instability in Procrustes | Confirm non-zero capacities and proper daylight window. |
